# 自托管运维

## 进程与存储

接入进程对外处理管理 API 和 HLS。默认启动一个本地调度循环，多实例可用 `serve -schedule=false` 配合独立的 `scheduler`。调度可以由多个进程同时运行，会话行锁保证只有一份待处理转码作业。

每个工作节点先通过 `media-stream node -name <name> -slots <n>` 注册，再启动 `media-stream worker -node <name> -concurrency <n>`。每个节点使用不同名称。数据库控制该名称下的作业总数。加 `-disabled` 更新注册状态可停止为节点分配新任务，已领作业可以在租约内完成。FFmpeg 子进程随父任务取消，30 秒租约可以续期。只有同一节点、尝试号、会话代际和当前序号可以提交结果。

进程需要同一套 MySQL 元数据和共享的受控媒体目录，目录需支持同文件系统原子改名。对象数据先写临时文件，刷盘后改名，最后提交数据库记录。目录应只授权给平台进程，避免经任意静态服务绕过访问控制。给媒体盘、MySQL、调度和转码分别配置资源与告警。

| 设置 | 作用 |
| --- | --- |
| `MEDIA_STREAM_MYSQL_DSN` | 单独数据库与专用账号，运行及迁移命令均读取 |
| `MEDIA_STREAM_SIGNING_KEY` | 32 字节十六进制密钥，`keygen` 生成。所有接入进程共用 |
| `MEDIA_STREAM_PUSH_TOKEN` | 单路推流器进程用短期凭据 |
| `-media` | 持久媒体目录，各节点指向相同路径内容 |
| `-listen` | 默认 `127.0.0.1:8080` |
| `-tls-cert`、`-tls-key` | 对非回环地址启用直接 TLS |
| `-secure-proxy` | TLS 代理连接回环地址时启用 Secure 播放 Cookie |
| `-input-slots` | 并发解码验证，默认 4 |
| `-threads` | FFmpeg 单进程编解码线程上限，默认 2 |
| `-concurrency` | 工作进程的本地作业并发，受数据库节点额度约束 |
| `-retention-grace` | 回收宽限，默认 24 小时。最短 1 分钟用于可重置演练 |

支持同网段共享文件系统和单机目录。公开服务通过 HTTPS，反向代理需透传授权头、Cookie、范围请求和响应状态。播放清单与分片都受授权，缓存策略默认为 `private, no-store`。接入端限定 MPEG-TS 和单片 24 MiB，公开推流凭据应按频道与输入分别发放。FFmpeg 需及时更新，由部署者按自己的风险边界隔离运行用户与媒体根。

## 升级

1. 停止接入新节目，等待会话归档与剪辑完成。停写后做一致性备份。
2. 用升级目标二进制运行 `media-stream migrate`。若迁移记录为 dirty，先查失败的 DDL，再根据备份回滚或修复，禁止在业务高峰以重复强制迁移掩盖错误。
3. 启动接入和至少一个已注册节点，读回 `/readyz`、旧频道、历史回放与一个带字幕剪辑。
4. 验证主备输入、节点心跳和旧授权有效期，随后放开新节目。

迁移 1 保存频道、身份与会话；迁移 2 增加媒体、转码与回放；迁移 3 增加字幕、剪辑和用量。测试会从迁移 1 的旧记录升级，并用同一凭据验证原记录和新输入。

## 备份与恢复

暂停推流、调度与写入，再执行快照。必须同时备份 MySQL、媒体目录和签名密钥，密钥单独加密保存。

```text
mysqldump --single-transaction --hex-blob --no-tablespaces media_stream > media_stream.sql
```

恢复时建隔离空库并导入 SQL，将媒体目录恢复到独立路径。使用相同密钥和恢复后的 DSN 启动应用。按录制索引核对分片大小、SHA-256 和授权结果，播放一个含断点的回放，并读取最早一条剪辑与字幕。恢复校验通过后再切实际流量。

Windows PowerShell 建议用 mysqldump 的 `--result-file` 直接落盘，并用 mysql `source` 导入，避免管道解码破坏二进制字段。

## 下架与空间回收

到期或主动下架时先收回播放可见性。过宽限后删除录像索引。排队或执行中的剪辑会阻止删除源录像，剪辑完成后继续按独立期限提供 MP4 和字幕。回收器先把无有效引用的文件标记为待删除，再删物理内容并写回状态，重启后可继续。

`media-stream sweep` 额外检查超过 48 小时且无数据库记录的媒体文件。短期提交失败的文件保留这个宽限以处理数据库回执丢失。周期运维可将它放到低峰调度。

## 当前协议边界

- 公开播放使用 HLS。接入协议为时间戳化 HTTP MPEG-TS，由本地推流命令把 RTMP、SRT 或文件转为片段。
- 直播延迟含源切片、验证、转码和播放器缓冲。低延时 HLS、DRM、跨区域分发和 GPU 编码由部署者根据扩展需求处理。
- 播放端卡顿来自浏览器事件。FFmpeg、HTTP 与调度时间线分别记录，可对照分析。
- 独立部署需要可访问的 FFmpeg；Linux 构建包含 Go 二进制和内置播放器资源。
