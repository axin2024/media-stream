# 分布式直播与点播平台｜MySQL 数据与集成

## 持久化边界

MySQL 8.4 InnoDB 是本项目业务状态与授权关系的权威存储。租户身份进入业务唯一键与关联检查。媒体、文件、备份或模型大对象允许使用文件或对象存储，库内保存版本化引用、长度、摘要及所有者。派生缓存可从持久记录重新构建。

## 逻辑实体与事实来源

| 业务域 | 核心实体与必要字段 | 写入时必须维持的规则 |
|---|---|---|
| 频道与凭据 | channel(tenant,key,owner), stream_token(channel,role,expires) | 频道主设置活动时间窗和主备输入权限，播放资格与推流资格独立检查。 |
| 主备输入 | input_session(channel,source,epoch), switch_event(session,reason,offset) | 监测可解码帧和最近活跃时刻，切换只接受当前代际，保留源时间和统一媒体时基。 |
| 转码节点 | transcode_job(session,preset,epoch), rendition(session,track,state) | 按资源能力派发 FFmpeg 作业，节点租约和输出路径绑定代际，同频道各档采用对齐边界。 |
| 分发与播放 | segment(session,track,seq,digest), playlist(track,rev,watermark) | 只将完整可读分片写入清单；跨时间基切换标记断点；不同画质共用可对应时间轴。 |
| 录制与点播 | recording(session,started,ended), vod(recording,rev,state) | 记录真实起止时间、间隙和输入来源；生成定稿清单后才能发布点播资产。 |
| 字幕与剪辑 | caption(asset,lang,range_ref), edit(source,from_ms,to_ms,output) | 字幕与音视频使用明确时间基，裁剪产物保留与源回放映射，关键帧引起的偏移需报告。 |
| 质量与计量 | qoe_event(session,device,event_key), usage(tenant,window,bytes) | 将源中断、转码等待、出口问题及播放器信号分别统计，流量按租户与会话聚合。 |
| 内容运营 | publication(asset,audience,expires), media_gc(blob,refs,state) | 到期先撤销索引可见性，再按清单清理无引用文件；字幕、剪辑及恢复任务一起做引用检查。 |

## 事务、索引与对账

- **身份与约束**　频道＋代际标识输入，切片以会话、轨、序号唯一，回放清单绑定录制版本。
- **业务索引**　按频道和节目时间找回放，按节点和作业状态取待转码，按清单水位查缺片。
- **数据生命周期**　下架先撤销播放授权，再清理无引用媒体；保留计量摘要与剪辑来源。

每个频道只允许一个活动输入代际；片段以会话、轨、序号唯一登记，清单只引用已完成文件。

列表使用租户、业务状态、更新时间和稳定主键分页。外部事件保留来源、外部号、内容摘要、处理结果和业务对象引用。同键不同内容产生显式冲突；网络超时后按原键查单。跨存储发布应先确认文件持久，再发布其数据库引用；回收须验证没有有效引用。

## 集成契约

推流身份换取有期限的频道凭据；向播放器提供主清单、媒体清单与字幕；外部存储返回摘要和持久地址。

开播请求指定频道、主备输入和转码预设，返回会话与短期凭证；断流上报包含输入代际。

剪辑请求提交回放版本、起止时间和字幕轨，返回新资产、实际切点及来源区间。

## 数据恢复与核验

在隔离环境恢复 MySQL 和引用清单，校验样例的源对象、派生关系及最终结果。恢复后应能回答以下问题。记录检测、切换与首个可播片段时间，切换处显式标记不连续；回放不重复计片，可定位断点并导出指定区间。
