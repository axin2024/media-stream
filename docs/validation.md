## Windows 本地测试

```powershell
./scripts/test-mysql.ps1 -MySQLBin C:/tools/mysql/bin -FFmpeg C:/tools/ffmpeg/bin/ffmpeg.exe
./scripts/test-mysql.ps1 -MySQLBin C:/tools/mysql/bin -FFmpeg C:/tools/ffmpeg/bin/ffmpeg.exe -Scenario Rehearsal -Node (Get-Command node).Source
```

测试脚本建独立 MySQL 数据目录和回环端口，结束后关闭实例并清理本次夹具。对现有实例，可准备三个独立空库并设置 `MEDIA_STREAM_TEST_DSN`、`MEDIA_STREAM_TEST_UPGRADE_DSN`、`MEDIA_STREAM_TEST_HTTP_DSN` 与 `MEDIA_STREAM_TEST_FFMPEG`，再运行 `go test -count=1 -v ./...`。测试会写入测试库，请使用可重置的隔离环境。

本地实测使用 MySQL 8.4.13、FFmpeg 7.1 与 Go 1.26.0。4 秒合成源切分后覆盖两档编码与 MPEG-TS 范围下载。接管后真实清单含分片断点，剪辑回执为 0.800 至 2.400 秒，WebVTT 的两个重定位区间与预期一致。缺失的高码率分片被排除，剪辑使用对应低码率源片完成。

MySQL 回执测试先保存三个回放，提交第一项后断开原调用。另一连接回读两项待处理，继续执行时同时启动两个调用方，数据库只保留一次成功的版本变更、一次版本冲突和一次未找到。另测观众 403、同租户其他凭据及另一租户 404，已提交选集换内容返回 409。

## 旧版升级与独立恢复

用公开的 v1.0.0 Windows 安装包运行独立的接入端、转码节点与双路推流器，封存回放并生成剪辑。停止写入后升级到迁移 4，使用同一播放凭据读取原回放。升级后与 MySQL 加媒体目录的独立恢复库供出的备路源片、MP4 和 WebVTT 均匹配升级前的 SHA-256。恢复库保留了未确认的两项选集，执行结果为期限设置成功和回放未找到。 [升级及恢复结果](results/upgrade.json)

## 两路实时演练

用同一段 120 秒 720p 样片创建双输入，在 45 秒停主路。保留以下时间和文件。

浏览器验证需要 Node、Playwright 和含 H.264 支持的 Chrome。将 `MEDIA_REHEARSAL_PLAYWRIGHT` 指向本机 Playwright 包，`PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向 Chrome。通过 `-EvidenceDirectory` 指定新输出目录。额外传入前版发行可执行文件的 `-PreviousCLI` 参数，可在同一段演练中核对升级前后的旧回放、分片、剪辑和字幕。

- 主路实际停止、平台检测、备路接管、首个备路片段提交和清单可见时间。
- 播放器首次起播、缓冲起止、缓冲时长、观察到的画质切换。
- 完整 VOD 清单和源时钟索引，核对无重复序号。
- 20 至 40 秒的剪辑回执、MP4 摘要和重定位字幕。
- 保存机器、FFmpeg、MySQL、清单分片长度、运行命令和操作时间。

发布目标为停源后 12 秒内恢复可播，实际卡顿以播放器事件为准。短路径集成用例主要验证协议和数据一致性。

2026-11-26 在 Windows 上用 Chrome 158、双路 FFmpeg 7.1 进程与独立 MySQL 8.4.13 演练。主机为 Intel Core Ultra 7 155H，22 个逻辑处理器。两个 720p 输入共享同一媒体目录，4 秒分片，一个转码节点配置两个并发槽，每个任务最多两个 FFmpeg 线程。MySQL 缓存 32 MiB，最多 48 个连接。

第 45 秒停止主路。系统记录停源后 19.9 ms 选中备路，796.644 ms 提交首个备路分片。Chrome 实际从 720p 切至 360p，直播期间成功拉取 19 个备路序号的分片。手动切画质时记到一次 392 ms 卡顿，停源至播放器观测到备路期间没有新的等待事件。本次未记录播放器错误、出口错误和转码失败。封存结果有 30 个连续媒体序号，总时长 120 秒。点播可定位至 30 秒和 52 秒，20–40 秒剪辑可解码，字幕时间与请求区间一致。 [演练原始记录](results/rehearsal.json) · [浏览器事件](results/browser.json) · [点播清单](results/vod.m3u8) · [源与媒体时钟索引](results/media-index.json)

在恢复库工作台选中回放后，浏览器故意丢弃准备请求已提交后的响应。重新登录能找回同一选集，执行响应被丢弃后再次查回原回执。实际发出一次准备和一次执行，回放版本从 2 变为 3。下架后原回放返回 404，独立授权剪辑摘要保持一致。 [批次浏览器记录](results/visibility-browser.json)

上述时延来自同一台主机的一组双输入、一个播放器和一个转码节点。预切换窗口测量从开播至第 45 秒，稳定观察持续至 120 秒样片结束。请求和错误计数收录在原始记录中。
