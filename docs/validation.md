# 验收与复现

需求基线定义 16 项场景，见 [验收 PRD](requirements/04-验收与运营-prd.md)。下表区分数据库、真实媒体、工作台和时延证据。

| 验收项 | 可重复验证 |
| --- | --- |
| AC-01 和 AC-02 | MySQL 验证角色、跨租户、撤销与过期凭据；HTTP 验证观众无法接入 |
| AC-03 和 AC-04 | MySQL 验证唯一活动输入、旧源作业拒绝、输出时钟；真实 HTTP 读取接管后分片和断点 |
| AC-05 和 AC-06 | 强制缩短旧作业租期，另一注册节点接管，旧节点的提交失效；生成降级清单 |
| AC-07 | FFmpeg 实际生成 720p 和 360p，HTTP 可读取两档且序号一致；浏览器切换与时延另记 |
| AC-08 | 移除一个实际高码率分片，直接请求返回 404，主清单保留完整低码率 |
| AC-09 和 AC-10 | 回放封存、媒体清单完整、结束重试保持同一回放 |
| AC-11 和 AC-12 | 真实两种分辨率片段生成 MP4，验证字幕重定位；倒序区间被拒绝 |
| AC-13 和 AC-14 | MySQL 验证播放器指标幂等；两输入实时演练输出源切换与浏览器卡顿两种证据 |
| AC-15 和 AC-16 | MySQL 引用保护与长期可见性；HTTP 验证下架后剪辑仍可授权读取 |

## Windows 本地测试

```powershell
./scripts/test-mysql.ps1 -MySQLBin C:/tools/mysql/bin -FFmpeg C:/tools/ffmpeg/bin/ffmpeg.exe
```

测试脚本建独立 MySQL 数据目录和回环端口，结束后关闭实例并清理本次夹具。对现有实例，可准备三个独立空库并设置 `MEDIA_STREAM_TEST_DSN`、`MEDIA_STREAM_TEST_UPGRADE_DSN`、`MEDIA_STREAM_TEST_HTTP_DSN` 与 `MEDIA_STREAM_TEST_FFMPEG`，再运行 `go test -count=1 -v ./...`。测试会写入测试库，请使用可重置的隔离环境。

本地实测使用 MySQL 8.4.13、FFmpeg 7.1 与 Go 1.26.0。4 秒合成源切分后覆盖两档编码与 MPEG-TS 范围下载。接管后真实清单含分片断点，剪辑回执为 0.800 至 2.400 秒，WebVTT 的两个重定位区间与预期一致。缺失的高码率分片被排除，剪辑使用对应低码率源片完成。

## 两路实时演练

用同一段 120 秒 720p 样片创建双输入，在 45 秒停主路。保留以下时间和文件。

- 主路实际停止、平台检测、备路接管、首个备路片段提交和清单可见时间。
- 播放器首次起播、缓冲起止、缓冲时长、观察到的画质切换。
- 完整 VOD 清单和源时钟索引，核对无重复序号。
- 20 至 40 秒的剪辑回执、MP4 摘要和重定位字幕。
- 保存机器、FFmpeg、MySQL、清单分片长度、运行命令和操作时间。

发布目标为停源后 12 秒内恢复可播，实际卡顿以播放器事件为准。短路径集成用例主要验证协议和数据一致性。

2026-11-25 在 Windows 上用 Chrome 158、双路 FFmpeg 输入与独立 MySQL 进行实时演练。第 45 秒关闭主输入，停源到首个备路分片提交为 **953 ms**。浏览器从 720p 切至 360p 后持续播放，本次报告记录 0 次卡顿、0 次播放器错误。封存录像包含 30 个分片和完整 120 秒源时长，点播定位和 20–40 秒剪辑通过。使用独立恢复库读回备路分片和剪辑，新旧摘要一致。 [演练原始记录](results/rehearsal.json) · [浏览器事件](results/browser.json)
